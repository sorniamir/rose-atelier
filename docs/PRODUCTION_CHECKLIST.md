# چک‌لیست راه‌اندازی فروشگاه واقعی

این پروژه فعلاً یک ویترین تعاملی و نمونه نمایشی است. موارد زیر باید پیش از دریافت وجه از مشتری تکمیل شوند.

## ۱. تصمیم‌های کسب‌وکار
- [ ] تأیید نام برند، لوگو، رنگ‌ها، دسته‌بندی‌ها و متن‌های نهایی
- [ ] دریافت فهرست کالا، SKU، قیمت، تصاویر مجاز، سایز/رنگ و موجودی واقعی
- [ ] مشخص‌کردن کشور ثبت کسب‌وکار، واحد پول، مالیات، ارسال، مرجوعی و پشتیبانی
- [ ] انتخاب درگاه پرداخت مناسب پذیرنده (برای ایران یا بازار بین‌المللی، بر اساس محل ثبت کسب‌وکار)

## ۲. زیرساخت و امنیت
- [ ] ایجاد یک پروژه Supabase مستقل برای فروشگاه؛ از دیتابیس اپلیکیشن دیگری استفاده نشود
- [ ] اجرای migration موجود در supabase/migrations
- [ ] ساخت حساب مدیر با Supabase Auth و افزودن شناسه او به public.store_admins از طریق SQL Editor
- [ ] تنظیم redirect URLs, password policy, rate limiting و SMTP تولیدی
- [ ] اعمال و بررسی RLS و اجرای Security Advisors پس از migration
- [ ] تعیین سیاست backup، retention، monitoring و مدیریت خطاها
- [ ] کلید secret/service role فقط در محیط سرور/Edge Function؛ هرگز با پیشوند NEXT_PUBLIC یا در مرورگر قرار نگیرد

## ۳. سفارش و پرداخت
- [ ] ساخت API یا Edge Function که هویت مشتری را سمت سرور بررسی کند
- [ ] محاسبه قیمت نهایی بر اساس دیتابیس سمت سرور، نه مبلغ ارسالی مرورگر
- [ ] قفل اتمیک موجودی در تراکنش، جلوگیری از فروش بیش از موجودی و پشتیبانی از لغو/بازپرداخت
- [ ] پیاده‌سازی درگاه با کلید sandbox، callback امضاشده و verify سمت سرور
- [ ] پرداخت تا قبل از verify قطعی، paid نشود؛ callback تکراری باید idempotent باشد
- [ ] تعریف چرخه وضعیت سفارش: pending_payment, paid, processing, shipped, delivered, cancelled, refunded
- [ ] ارسال رسید و اعلان سفارش با ارائه‌دهنده ایمیل/SMS
- [ ] آزمایش هم‌زمانی دو سفارش برای آخرین واحد یک کالا، callback تکراری و پرداخت ناموفق

## ۴. مدیریت و محتوا
- [ ] پنل مدیر فقط برای کاربران دارای نقش مدیر قابل استفاده باشد
- [ ] ایجاد/ویرایش/آرشیو کالا و مدیریت سایز، رنگ، SKU، قیمت، تصاویر و موجودی
- [ ] ثبت تاریخچه تغییر موجودی و علت تغییر (فروش، برگشت، اصلاح دستی)
- [ ] بارگذاری تصاویر در Storage خصوصی/عمومی با محدودیت نوع و حجم
- [ ] تکمیل صفحات سیاست حریم خصوصی، شرایط خرید، تحویل و مرجوعی

## ۵. قبل از انتشار عمومی
- [ ] اتصال دامنه و TLS، تنظیم DNS و redirect دامنه اصلی
- [ ] بررسی نمایش موبایل، دسترس‌پذیری، فرم‌ها، خطاها و empty states
- [ ] بهینه‌سازی تصویرها، favicon، metadata و تصاویر اجتماعی
- [ ] تست E2E مسیر محصول → سبد → سفارش → پرداخت → تأیید
- [ ] حذف سفارش‌ها/محصولات نمونه، پاک‌سازی هرگونه داده آزمایشی
- [ ] بررسی مجوز تصاویر و جایگزینی placeholderها با محتوای دارای حق استفاده
- [ ] انجام سفارش آزمایشی از ابتدا تا انتها و سپس تأیید کارفرما برای فعال‌سازی live mode

## معیار پذیرش
فروشگاه فقط وقتی آماده فروش واقعی است که تراکنش آزمایشی درگاه تأیید شود، سفارش از سمت سرور ایجاد شود، موجودی در دیتابیس کاهش یابد، مدیر بتواند سفارش/موجودی را مدیریت کند، و دسترسی کاربر عادی به داده‌های مدیریتی با تست RLS رد شود.
